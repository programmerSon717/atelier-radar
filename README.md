# atelier-radar

일본 · 한국 · 대만 건축설계 분야의 **신입공채 / 전환형 인턴(conversion track)** 공고를
상시 수집·검증해서 텔레그램으로 밀어주는 에이전트.

대상 조건: M.Arch 2027년 5월 졸업 예정 · 대만 국적 · 정규직 경력 없음 · 일본어 불가.
프로필: `data/profile/profile.yaml` (신원 정보는 담지 않는다 — 공개 저장소다)

---

## 이 봇이 지켜야 할 원칙

1. **추측 금지.** 모든 항목에 출처 URL + 확인 날짜를 붙인다.
   모르면 지어내지 않고 `확인 안 됨` 을 그대로 출력한다.
   틀린 공고 하나가 지원자의 시간을 통째로 날린다.
2. **오피스 단위로 추적.** 회사 단위가 아니다.
   켄고쿠마 도쿄(전환형 인턴 있음)와 서울(규모 작음, 불명)은 완전히 다른 건이다.
3. **언어 요건은 1급 필드.** 후보자는 일본어를 못 하고 한국어가 초급이다.
   일본어/한국어 필수 여부를 못 밝히면 그 공고는 "검증 미완"으로 남긴다.
4. **새 공고만 알림.** 이미 보낸 건 다시 보내지 않는다(dedup).
5. **다국어 분리.** 출력 문구는 `config/locales/` 로 분리. ko → zh-TW 전환이 스위치 하나.

## 아키텍처

```
스케줄러 (30분 주기)
  └─ orchestrator
       ├─ 오피스 목록 로드 (data/targets/*.yaml)
       ├─ ★ 서브에이전트 병렬 fan-out — 오피스 1개 = 워커 1개
       │    각 워커: 채용페이지 + 잡보드 검색 → 공고 추출 → 언어요건 확인 → 출처 기록
       ├─ 수집 결과 정규화 → JSON 스키마 검증
       ├─ dedup (store/seen.sqlite) → 신규만 통과
       ├─ 매칭 판정 (졸업연도 / 언어 / 비자 / 학위)
       └─ 텔레그램 발송
```

**서브에이전트가 필요한 이유:** 오피스마다 정보 출처와 구조가 전부 다르고
(일본=リクナビ, 한국=사람인+자사, 대만=104), 오피스 하나를 깊게 파야 한다.
40여 개를 순차로 돌면 느리고, 한 곳에서 막히면 전체가 멈춘다.
병렬로 뿌리면 몇 분에 끝나고 실패도 그 오피스에만 갇힌다.

## 비용 — 이 프로젝트에서 두 번째로 중요한 이슈

43개 오피스를 30분마다 전부 LLM 으로 조사하면 **하루 $600을 넘는다.**
(오피스당 약 $0.2 × 43 × 48회) 채용 공고는 그렇게 자주 바뀌지 않으므로 순전한 낭비다.

그래서 3단으로 나눴다:

| 단계 | 무엇을 | 주기 | 비용 |
|---|---|---|---|
| Tier 1 `watch` | 채용페이지 HTTP GET → 텍스트 해시 비교 | 30분 | **$0** (LLM 안 씀) |
| Tier 2 `research` | 해시가 바뀐 오피스만 Claude 조사 | 변경 시 | 하루 $0~1 |
| Tier 3 `sweep` | 전체 훑기 + 잡보드 검색 | 주 1회 | 회당 ~$8 |

체감은 실시간이면서 월 $60 선에서 유지된다.

## 실행

```bash
./.venv/bin/python -m src.main --dry-run          # 발송 없이 확인
./.venv/bin/python -m src.main                    # 평소 실행 (Tier1 → 2)
./.venv/bin/python -m src.main --sweep            # 전체 훑기
./.venv/bin/python -m src.main --only kr-101      # 한 곳만
```
